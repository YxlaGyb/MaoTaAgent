# 文档约定

[English](CONVENTIONS.md) | 中文

## 语言对

- 双语文档是同一目录下的三文件组：英文 `x.md`、中文 `x.zh.md`，以及记录两侧 git blob 哈希的 `x.i18n.yaml`。
- 两种语言地位相同：先写哪一侧都可以，同一次改动里把另一侧带上，然后用 `pnpm run i18n:write <x.md>` 重新记录。语言对整份合并。
- 每个文件在自己的 H1 下直接带一行语言切换，点名两种语言并链接另一侧：英文文件链 `x.zh.md`，中文文件链 `x.md`。`pnpm check` 会校验这一行的确切措辞与记录的哈希，所以从已有的语言对里复制这一行，不要重新敲。
- 中文一侧镜像同样的章节顺序与标题，使用已有语言对里的惯用中文名。从邻近的语言对里复制它们，不要自创或另译。
- 只有语言对与它的切换行带中文，仓库里其他文件一律用英文写。

## README 的种类与形状

- 包的 README 用它所在位置隐含的种类：`packages/<group>/README.md` 是 `package-group` 地图，从不重述某个包的契约，而 `packages/<group>/<pkg>/README.md` 是拥有该契约的 `package-reference`。
- YAML 前言带 `description` 与 `kind`。
- 保持种类所点名的形状：不超过 100 词的概述、每个被链接章节都有锚点的目录、为契约接受的每一类输入配一张表的 `Use this package`、`Understand the implementation`，以及在有兄弟文档可指向时的 `Further exploration`。
- 没有限制章节。读者必须知道的边界写进 `Use this package` 或 `Understand the implementation`，作为一句平实的事实陈述；确实没做完的事根本不进 README：要么做完，要么写成 `Dev Note`（开发备注）的开放问题。有意留到后面的工作改登记在 `docs/pending.md`，一个缺口一条，每条写明要改哪个文件。
- `Dev Note` 是可选的，只在存在真实开放问题时才写；没有时就把这一节整个省略，而不是写一个占位。

## 平实的行文

- 文档保持平实：不要折叠块，不要 “click to expand” 这类标签，不要自创或装饰性的章节名。

## 避免装饰性图标

- 文档里不要使用 emoji 或图标（例如 🔒、✅、⚠️、🟢），它们在不同操作系统与字体下渲染不一致，反而降低可读性。
- 一切都用文字表达清楚：
- 状态或结果用明确的词：是/否、支持/不支持、已完成/进行中/未开始、正常/异常、高/中/低。
- 表格的状态列用文字，而不是 ✅、❌、🟢、🔴 这类符号；确实需要图例时，用文字版图例。
- 提示与警告用文字标签（例如“注意：”“重要：”“已实现：”），而不是 emoji 前缀。
- 以下用法可以接受（它们在等宽字体里渲染一致，且承担结构性而非装饰性作用）：ASCII 制表符（┌─┘├）、几何箭头（▲ ► ▼）、带圈数字（① ② ③）、纯文本箭头（→ ← ↓），以及文字形式的快捷键（例如 Cmd+K）。
- 尽量少用破折号或非文字符号，保持整洁的外观。

## 避免长破折号

- 两种语言的正文里都不要使用长破折号或短破折号。
- 引入解释用冒号，连接分句用逗号或分号，补充说明用括号。
- 代码、旗标、文件名与复合词里的连字符不受影响。
