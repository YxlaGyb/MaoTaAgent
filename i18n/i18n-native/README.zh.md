# i18n-native

[English](README.md) | 中文

## 概述

保管界面文案的插件。它提供 `i18n` 能力，去找每一个提供 `i18n.<namespace>` 能力的其他插件，问每个插件写哪些语言、再问它的词，然后把这些回答折成一份目录。没有任何注册与注销：能力表就是唯一的注册表，所以拥有词的插件随时可以挂上或摘掉，存储用同一种方式发现它。它不管理读它的前端。前端一次性拿走目录并自己留一份，因为正在打字的人必须立刻看到词，而不是等一个来回完成。

<a id="use-this-package"></a>
## 使用本包

通过 `i18n` 能力调用。

| 方法 | 参数 | 返回 |
|---|---|---|
| `catalog` | 无 | `{ locale, languages, namespaces, catalog, problems }`，前端自己回答查找所需的全部东西。 |
| `translate` | `{ key, namespace?, locale? }` | `{ locale, text }`，同一次查找，供已经在线的这一侧使用，例如宿主自己写出的消息。 |

| 回包字段 | 含义 |
|---|---|
| `locale` | 一切应当据此渲染的语言：档位里的偏好对着声明的语言和机器的说法解析出来的结果。 |
| `languages` | 声明的语言，这样前端不必自己再存一份表就能把它们列出来。 |
| `namespaces` | 有回答的命名空间，已排序。 |
| `catalog` | 折好的词，每个命名空间每种语言一份 `Messages`。 |
| `problems` | 折叠与对齐检查发现的问题，前端可以显示或记下。 |

`translate` 原样回答那个词、不做任何替换：有值要填的调用方自己格式化，这样线格式里就少一个标识符。

### 配置

| 键 | 默认值 | 含义 |
|---|---|---|
| `locale` | `"system"` | 用哪门语言渲染。`system` 是问机器；其余的值拿去和声明的语言匹配。 |
| `languages` | 内置的那一对 | 这个部署声明的语言，每项是 `{ id, label, fallback }`。形状不对的列表会被整体忽略，而不是部分读进来。 |

### 提供方契约

插件通过提供 `i18n.<namespace>` 能力并回答两个方法来交付。

| 方法 | 回答 |
|---|---|
| `describe` | `{ locales }`，它有词的语言。 |
| `catalog` | `{ namespace, messages }`，每个 locale 一份 `Messages`。 |

一个交付者会被逐个问它声明过的语言，而它的回答会对着那张表读。声明了却什么都没回答的语言、回答了却从未声明的语言，都是 warning，它其余的词的照用。

<a id="understand-the-implementation"></a>
## 理解实现

### 源码地图

| 文件 | 职责 |
|---|---|
| [`src/engine.ts`](src/engine.ts) | 找交付者：能力前缀、那两次调用、以及各种跳过。 |
| [`src/plugin.ts`](src/plugin.ts) | `i18n` 能力：它的配置、折叠、`catalog` 与 `translate`。 |
| [`src/index.ts`](src/index.ts) | 内核启动的入口：它运行这个 definition。 |

### 为什么发现用前缀而不用注册表

存储从不保存交付者列表，因为列表会是"挂了什么"的第二份真相，而且恰好在插件挂上或摘掉的时候过期。改为能力表自己当注册表：`providerCapabilities` 用 `i18n.` 前缀筛这张表，于是插件挂上就交付、摘掉就不再交付，没有什么需要注册或注销。存储会在 `kernel.capabilities.changed` 上重读这张表，因为启动时拿到的那份快照是一个瞬间而不是一个事实。这与 `hooks-native` 处理它的提供方是同一个形状，这是有意的：两个存储针对各自的扩展点回答同一个问题。

### 为什么坏掉的交付者是跳过而不是致命

描述不出来、回答不出可读的词、或者回答得不成形状的交付者，会被跳过并记一条 warning。另一种做法是拒绝启动，比较一下就能定案：少一个命名空间的界面会在本该是一句话的地方显示一个键，人看得见、报得出来，而因为某个插件的词写歪了就拒绝启动的界面则完全用不了。同一套推论在交付者内部也逐字段成立：声明了却答不出的语言就丢掉，答得出的照留。

### 为什么整份目录过线

存储交出去的是一整份目录，而不是一次回答一个查找，因为渲染必须是同步的。逐个键去问存储的前端会先显示一个键、等一会儿、再显示那句话，而这正是折叠要避免的；所以前端自己留一份。这也决定了存储不是什么：它不是决定当前生效语言的那个组件，因为前端会从同一张语言表自己解析，偏好变了也不需要向这个进程问任何东西。

### 三件事划定这个存储的边界

语言在启动时读一次，形状不对的档位会得到内置那一对，因为配置是持久边界，读不出来的表就不是一张可以半用的表。能力一变目录就整体重建，所以交付者的错由下一次发现来纠正，而不是被打补丁。这里没有任何东西活过进程：abort controller 的存在只是为了让内核道别时仍在飞行中的那次发现跟着停下来。
