# interaction/：动手之前先问

[English](README.md) | 中文

## 摘要

这里只有一个包：工具在做破坏性的事之前去问的那道闸门。它和别的插件一样是插件，所以内核路由 `permission` 时不认识工具、也不认识命令；而一个从不挂载它的部署会拒绝每一个命中风险的操作，而不是放行。这一页说清这个包组答什么，契约在它自己的目录里。

<a id="包"></a>
## 包

| 包 | 目录 | 能力 | 职责 |
|---|---|---|---|
| `@maota/permission` | [`permission`](permission/) | `permission` | 闸门：会话的档位、还在等回答的问题，以及成对留痕的审计文件。 |

分工在于"发问"与"决断"。某个操作值不值得问一句，由工具自己判断，因为只有工具知道自己的参数会做什么；档位、等待和留痕归闸门。于是第二个应答者（例如策略引擎或桌面弹窗）可以在工具毫无改动的情况下替代 web 卡片：它注册自己，`tool-pwsh` 照旧只读那四个结果词。
